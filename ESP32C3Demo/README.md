# ESP32-C3 OLED 引脚调查（锁定版）

本工程默认环境只用于保存候选映射和读取 GPIO 电平，不进行 ACK、I2C、复位或
主动拉低操作。另有一个必须显式选择的受限开漏测试环境；它不扫描、不输出高
电平，每次只允许一个 GPIO 拉低 5 秒，或显式选择唯一允许的 P9+P10 双线组合。
现阶段不要把“候选”当作已确认的屏幕引脚定义。

## 当前结论

| OLED 脚 | 当前判断 | 置信度与限制 |
|---:|---|---|
| 13 | VSS / VLL 参考地 | 已作为全部低压测量的参考点 |
| 6 | 外部 VDD 候选 | 强工作假设，尚待功能响应确认 |
| 7 | 内部 VLH 候选 | 禁止外部供电，保持悬空 |
| 8 | D2 / SDAOUT 候选 | 尚待 ACK 确认 |
| 9 | D1 / SDAIN 候选 | 尚待 ACK 确认 |
| 10 | D0 / SCL 候选 | 尚待 ACK 确认 |
| 11 | D/C# / SA0 候选 | 尚待 ACK 确认 |
| 12 | RES# 候选 | 尚待 ACK 确认 |
| 1、15 | 同一未知模拟/面板轨候选 | 两脚之间约 11.7 ohm，禁止供电 |
| 14 | 未知模拟节点 | 禁止供电，也不连接 GPIO |

`pin6` 弱供电后 `pin7` 会建立接近的电位；而给 `pin7` 增加 51 kohm 对地负载时，
供电电流明显增加。这与“pin6 是外部 VDD、pin7 是内部 VLH”相符，但仍不是最终
功能证明。

## 已通过的最终静态组合

所有改线均在断电状态完成，本组合没有连接 ESP32-C3：

```text
实验电源正极 3.01 V -- 33 kohm -- OLED pin6
实验电源负极 -------------------- OLED pin13

OLED pin8  -- 51 kohm -- OLED pin6
OLED pin9  -- 51 kohm -- OLED pin6
OLED pin10 -- 51 kohm -- OLED pin6
OLED pin12 -- 51 kohm -- OLED pin6
OLED pin11 -- 51 kohm -- OLED pin13

OLED pin7 悬空
OLED pin1、pin14、pin15 悬空
```

这里每一行的 `51 kohm` 都是独立电阻，不能把信号脚直接并联。最终重复测得：

```text
33 kohm 两端压降 = 0.15 V
计算总电流       = 0.15 V / 33 kohm = 约 4.55 uA
电源状态         = CV
读数             = 稳定，无自行变化
异常             = 无
```

这只说明该弱偏置组合没有表现出异常负载。它不能证明五个数字脚的具体功能，也
不能证明屏幕已经满足正常工作的供电条件。测量完成后应先断电。

另外两项用于形成工作假设的记录：

```text
pin7 悬空时，33 kohm 压降约 0.16 V（约 4.85 uA）
pin7 经 51 kohm 接 pin13 时，33 kohm 压降 1.04 V，pin7 对 pin13 为 1.46 V
```

## ESP32-C3 候选连接

开发板图片方向为天线朝上、元件面朝前。物理排针编号不是 GPIO 编号。

| OLED 脚 | ESP32-C3 GPIO | 开发板物理排针 | 候选功能 |
|---:|---:|---:|---|
| 8 | GPIO0 | 左侧 02 | D2 / SDAOUT |
| 9 | GPIO1 | 左侧 03 | D1 / SDAIN |
| 10 | GPIO3 | 右侧 20 | D0 / SCL |
| 11 | GPIO4 | 右侧 28 | D/C# / SA0 |
| 12 | GPIO5 | 右侧 27 | RES# |

这些 GPIO 避开了 GPIO2/8/9 启动绑带脚、GPIO12/13 板载 LED、GPIO18/19 原生
USB 和 GPIO20/21 UART0。当前阶段仍然暂不把 ESP32-C3 接到 OLED。

## 锁定固件

固件只接受以下串口命令：

```text
PINS    只读 GPIO0/1/3/4/5 的数字电平
STATUS  显示锁定状态和候选轨定义
HELP    显示命令与候选映射
```

`SCAN` 以及任何以 `ARM` 开头的命令都会被拒绝。五个 GPIO 在程序启动、主循环和
每条命令前后都会被设为无内部上下拉的高阻输入。浮空输入的 `PINS` 读数可能变化，
不能单独作为引脚判断依据。

源码还包含编译期硬锁：将 `OLED_POWERED_PROBE_ENABLED` 设为非零值会直接编译
失败，而不是解锁旧扫描代码。旧的 pin15 供电、pin14 GPIO 和自动交换 SDA 方向
扫描路径已经删除。

## 后续 ACK 前置条件

- 当前 `33 kohm` 供电串阻只适合静态微电流验证，不能直接运行 I2C。
- `pin7`、`pin1`、`pin14`、`pin15` 都不得外部供电。
- 后续数字总线上拉只能接到 OLED `pin6` 所在的受控逻辑电源，不能接 ESP32-C3
  的 `3V3`。
- GPIO 只能采用开漏拉低或高阻释放，不能主动输出高电平。
- 必须先验证动态拉低时 `pin6` 不会塌陷，再编写并审查固定映射的 ACK 固件。
- 任何接线修改都必须先断电；出现 CC、发热、异味、亮点或电压持续下降时立即
  断电。

在这些条件形成新的、单独审查过的测试方案以前，不运行 ACK，也不恢复旧扫描。

## 受限开漏测试环境

`open_drain_test` 与默认锁定环境使用不同的源文件。默认构建仍然是只读固件；测试
环境只能用 `-e open_drain_test` 显式选择。它具有以下硬限制：

- 上电及空闲状态下，五个 GPIO 都是无内部上下拉的高阻输入。
- 单线测试只能选择 `P8`、`P9`、`P10`、`P11` 或 `P12` 中的一路。
- 必须先发送 `ARM Pn`，再于 15 秒内发送匹配的 `CONFIRM Pn`。
- 仅使用开漏方式拉低，5 秒后自动恢复高阻。
- ACK 前最坏负载测试只允许显式的 `ARM P9+P10` 和
  `CONFIRM P9+P10`；其他双线组合均不存在。
- 双线配置或低电平回读失败时会立即恢复高阻，不等待 5 秒。
- 不提供高电平输出、自动扫描、连续脉冲或 ACK 测试。

只编译、不上传：

```sh
/Users/liyao/.platformio/penv/bin/pio run -e open_drain_test
```

测试环境在完成单独审查前不得上传。上传及物理测试时仍必须保留每路 `10 kohm`
串联电阻、独立 `51 kohm` 偏置电阻、受限的 OLED `pin6` 供电及共同地线。
